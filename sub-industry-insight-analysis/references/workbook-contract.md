这份参考文件定义当前“细分行业普惠信贷分析”工作簿的稳定接口。若用户提供了新模板，以用户模板为准，但必须保留下列语义：原始数据可回溯、同一 `TRACE_CODE` 的多 `prod_cd` 在行业汇总层合并、专家假设与客户证据分离。

## 输入与血缘

### 原始行业贷款数据

按表头识别下列语义字段：

| 语义 | 当前常见字段 | 处理 |
|---|---|---|
| 产品/成员代码 | `prod_cd` | 字符串保留；只作为行业组成员维度 |
| 行业主键 | `TRACE_CODE` | 清洗首尾空格后作为唯一行业组键 |
| 来源数值 | `_col0` 或来源实际列名 | 仅按原始标签记录；可在同组内汇总时注明来源口径 |
| 行业名称 | `细分行业` | 原样保留；用于展示和代码名称一致性检查 |

不要把列位置、固定总行数、固定 `prod_cd` 集合写成通用规则。原始明细应保留 `source_file`、`source_sheet`、`source_row`；无法获得文件哈希时至少记录文件路径和运行时间。

### 指标字典

指标字典是正式指标 ID 的唯一来源。解析后至少保留：

`indicator_id`、`indicator_name`、`indicator_type`、`source_row`、`raw_text`。

组合指标保留为组合项，不能把组合名称拆成未经登记的正式 ID。行业明细中的每个 ID 必须能反查到字典行；反查失败应阻止该 ID 写入正式明细。

### 增量范围

用旧工作簿已存在的 `TRACE_CODE` 集合与源数据首次出现顺序计算后续批次。用户指定代码时按用户顺序校验；同一行业代码的所有原始行都进入样本区。输出新版本，不覆盖旧版本。

## 工作表契约

所有表通常从第 4 行开始表头、第 5 行开始数据；标题和说明放在第 1 行附近。若模板不同，保持字段语义和可审计公式，不强行改变用户布局。

| 工作表 | 表头/关键范围 | 必须表达的内容 |
|---|---|---|
| `说明` | `A1:H*` | 使用顺序、运行版本、状态定义、非自动审批边界 |
| `原始筛选样本` | `A4:D*` 或等价范围 | 本次用户样本和新增行业全部原始行，不去掉同组成员 |
| `原始行业贷款数据` | `A4:D*` 或等价范围 | 原始行业数据只读快照，保留源表结构 |
| `行业总览` | `A4:L*` | 每个 `TRACE_CODE` 一行的行业级总览 |
| `行业规则` | `A4:O*` | 每个行业的专家调查—授信—风险规则 |
| `行业指标明细` | `A4:O*` | 行业 × 指标的可执行证据和专家分层 |
| `准入及风险框架` | `A4:H*` | 通用状态机、人工动作和决策边界 |
| `指标300原表` | `A4:F*` 或等价范围 | 指标字典只读复制、解析和引用标记 |
| `来源与口径` | `A4:C*` | 来源、字段限制、版本、缺口和待验证材料 |

### `行业总览`

推荐列序：

1. `TRACE_CODE`
2. `细分行业`
3. `样本记录数`
4. `来源指标值合计`
5. `来源指标值原样`
6. `prod_cd`
7. `经营闭环`
8. `行业独特逻辑`
9. `第一还款来源/授信结构`
10. `行业层面结论`
11. `主要人工复核触发`
12. `贷后监测重点`

`样本记录数`和`来源指标值合计`应从 `原始筛选样本` 用公式计算；不要把运行时计算结果硬编码为静态数值。若来源值不可加或单位未知，显示原样值并在`来源与口径`说明限制。

### `准入及风险框架`

推荐列序：`环节`、`硬门槛/指标簇`、`判断逻辑`、`正向证据`、`红旗/冲突`、`建议输出状态`、`人工动作`、`备注`。

至少覆盖：主体与授权、经营真实性、现金流与偿债、外部风险与合规、行业专属指标、贷后触发、最终授信。最终授信行必须说明由有权审批人或正式制度产生最终结论。

## 行业规则与指标明细

### `行业规则`

推荐列序：

`TRACE_CODE`、`细分行业`、`行业特点`、`经营闭环`、`独特分析逻辑`、`调查证据`、`第一还款来源/授信结构`、`行业层面准入`、`正向逻辑链（事实→含义）`、`反向逻辑链（异常→风险）`、`建议贷后`、`核心指标ID（原表）`、`个性指标优先级/低解释力`、`行业常态/误判排除`、`资深信贷专家追问`。

规则文本应同时给出事实、解释、证据和下一步动作。例如“订单下降”不能直接等于风险；要追问订单取消原因、库存、客户集中、回款和债务安排。`行业层面准入`只能表达进入人工审查所需的证据条件。

### `行业指标明细`

推荐列序：

`TRACE_CODE`、`细分行业`、`调查阶段`、`指标簇`、`指标ID`、`指标名称（原表）`、`原表行号`、`本行业使用逻辑`、`可支持信号`、`预警信号`、`建议调查动作`、`证据边界`、`个性等级`、`相对通用行业的专家偏离`、`组合核验与误判排除`。

每个行业的指标都应能落到以下关系：

```text
指标 → 所需证据 → 支持信号/预警信号 → 调查动作 → 人工边界
```

`个性等级`只使用 `核心个性`、`重要补强`、`通用校验`。核心指标数量由行业规则和字典覆盖决定；模板通常要求至少形成一组可解释的核心个性指标，但证据不足时应标记缺口，不为了凑数发明 ID。

## 计算与状态

### 允许的计算

- 同一 `TRACE_CODE` 的原始记录数：按原始行计数；
- 来源数值合计：仅在字段可加、单位和统计粒度一致时求和；
- `prod_cd` 集合：去重后展示，但保留原始明细；
- 指标引用标记：按正式字典 ID 匹配；
- 公式结果：保留公式、输入范围和显示值。

### 不允许的推断

- 由行业规则文本推导客户收入、现金流、订单、库存、违约或审批结果；
- 由样本排序或规模字段推导行业平均、坏账率、PD、AUC、KS或统一阈值；
- 由一次异常推导自动拒绝；
- 由专家偏离推导“行业整体水平”。

### 状态语义

| 状态 | 输出含义 |
|---|---|
| `PRELIMINARY_PASS` | 进入人工授信审查，不是批准 |
| `MANUAL_REVIEW_REQUIRED` | 有冲突、红旗或关键证据需要人工判断 |
| `NOT_ENOUGH_DATA` | 关键数据、口径或时间窗不足 |
| `DEFER_OR_EXCLUDE` | 按制度暂缓或排除，不能由本工作簿自动执行 |

## 验收锚点

### 数据和映射

- 原始快照的行数与输入一致；
- 每个新增 `TRACE_CODE` 在总览、规则和明细中出现且不重复；
- 每个行业的 `prod_cd_set`、原始行数和源行定位与输入一致；
- 行业名称冲突、空值、`#N/A` 和未匹配指标均有质量记录；
- 每个 `coreIds` 都属于该行业指标集合并能反查指标字典。

### 公式和文件

- 关键汇总列是可见公式，公式引用的表名始终用单引号包裹；
- 生成区域不存在 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`；
- 源数据既有 `#N/A` 单独列为源异常，不误报为生成公式错误；
- 所有工作表至少完成一次渲染检查，长文本没有明显截断；
- 导出后 `unzip -t` 通过，并记录 SHA-256。

### 交付摘要

将以下字段作为运行摘要或交付消息：

`outputPath`、`runId`、`sourceSheet`、`sourceRows`、`uniqueIndustryCount`、`selectedIndustryCount`、`selectedRawRows`、`detailRows`、`missingIndicatorIds`、`mergeConflicts`、`formulaScan`、`visualReview`、`sha256`。
