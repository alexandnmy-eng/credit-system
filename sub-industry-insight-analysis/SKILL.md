# 细分行业洞察分析

## Overview

将原始行业贷款数据、行业规则和指标字典组织成可追溯的细分行业信贷本体，并生成可复核的 `.xlsx`。核心表达不是评分卡，而是：

`当前对象/状态 → 可执行动作 → 所需证据 → 适用规则 → 结果 → 下一跳 → 人工边界`

行业规则用于贷前调查、授信结构和贷后监测的专业提问，不直接替代客户级尽调、模型校准或有权审批。

## 适用请求

触发于以下请求：

- 从原始行业贷款数据继续分析后续 N 个细分行业；
- 生成或更新“行业细分普惠信贷分析”工作簿；
- 要求把相同 `TRACE_CODE` 下的不同 `prod_cd` 合并；
- 补充“专家规则型偏离”、正向/反向逻辑、个性指标、调查证据或贷后触发；
- 将行业洞察封装为信贷本体建模资产。

## 不可越过的边界

把下列规则当作硬性验收条件，不用“尽快交付”“已有旧结果”“行业经验足够”等理由绕过。

| 规则 | 必须做到 | 不能做 |
|---|---|---|
| 原始证据优先 | 保留原始行、源表、源行号或可定位范围 | 用旧工作簿或猜测替代原始数据 |
| 行业主键 | 用清洗后的 `TRACE_CODE` 分组；名称只作展示和校验 | 按行业名称或 `prod_cd` 拆成多个行业 |
| `prod_cd` 语义 | 作为行业组内成员维度，保留集合、行数和原值 | 把 `prod_cd` 当行业主键，或擅自解释其业务含义 |
| 指标字典 | 正式指标 ID 只能来自本次输入的指标字典 | 补造 ID、把名称猜成 ID、把组合项拆成未登记 ID |
| 专家偏离 | 明确是相对通用普惠调查模板的权重/证据偏离 | 把专家假设写成统计行业均值或已校准阈值 |
| 缺失和冲突 | 输出 `NOT_ENOUGH_DATA` 或 `MANUAL_REVIEW_REQUIRED`，并写明补证据动作 | 用 0、估算客户值或复制别行业值掩盖缺失 |
| 授信边界 | `PRELIMINARY_PASS` 只表示进入人工审查 | 自动审批、自动拒绝或生成客户违约事实 |
| 写入责任 | 只允许一个 artifact writer 改工作簿，其他分析只读 | 多个代理同时写同一工作簿 |

**特别注意：** 当前某个数据源若恰好有两条记录或 `prod_cd=1099/1221`，只能作为本次运行的观测结果；下一次必须重新读取和验证，不能写成通用假设。

## 工作流

### 1. 建立运行边界

先登记 `run_id`、输入文件绝对路径、源工作表、输入版本/校验值、输出目录和当前任务范围。若是增量更新，读取现有工作簿确认已覆盖的 `TRACE_CODE`，不得用硬编码数组代替覆盖检查；旧文件只读，输出新版本。

工作簿 authoring 使用 `load_workspace_dependencies` 提供的运行时和 `@oai/artifact-tool`。优先复用项目内已有的单一 `.mjs` builder，采用“补配置/补函数/重跑”的方式；不要另写一个平行 builder。不得用 `openpyxl`、`pandas.ExcelWriter` 或其他工作簿写入库。

### 2. 读取和审计输入

按表头识别字段，不依赖固定列号或固定总行数。至少定位：

- 原始行业贷款数据：`TRACE_CODE`、细分行业名称、`prod_cd`、来源数值列及源行号；当前工作簿常见表名为 `行业细分贷款数据`；
- 指标字典：指标 ID、指标名称/说明和原始行号；当前工作簿常见表名为 `指标300+`；
- 既有输出：`行业总览`、`行业规则`、`行业指标明细` 的现有覆盖范围和样式。

原始字段的含义、单位、统计周期未被来源明确说明时，保留原标签，只写“来源字段汇总/原样值”，不得解释成贷款余额、授信额度、风险分或违约率。源数据已有的 `#N/A` 应保留并标记为源异常，不与生成公式错误混淆。

### 3. 选择本批行业

按原始数据首次出现顺序生成唯一 `TRACE_CODE` 序列：

1. 清洗字符串空格，不改变代码本身；
2. 按 `TRACE_CODE` 首次出现去重；
3. 若用户给出代码，按给定代码校验并保留用户顺序；
4. 若用户说“后续 N 个”，从既有覆盖之后选择 N 个未覆盖代码；
5. 对每个代码核对原始行业名称，代码不存在、名称冲突或源行异常要单列报告。

行业名称相同但 `TRACE_CODE` 不同，不自动合并；应记录冲突并转人工复核。代码相同但名称存在空值或 `#N/A`，不根据代码猜名称。

### 4. 按 `TRACE_CODE` 合并并保留血缘

对本批和历史样本分别建立：

```text
industry_group = TRACE_CODE
industry_name = 原始名称（冲突时保留各原值）
raw_row_count = 该代码的全部原始行数
prod_cd_set = 该代码下全部 prod_cd 去重集合
source_rows = 源文件/源工作表/源行号列表
```

总览可以一行呈现一个行业，但原始明细必须完整复制；同一行业多个 `prod_cd` 只能在汇总层合并，不能丢掉任何成员。只有在源数据确实支持时才计算记录数和来源数值合计；比率、客户数或贷款余额等没有稳定粒度/字段定义时标记 `NOT_ENOUGH_DATA`。

### 5. 构建行业本体和专家规则型偏离

先把行业写成经营闭环，再形成规则：

`投入/采购 → 生产或服务交付 → 验收/开票/收单 → 回款 → 应收/库存/债务转换 → 第一还款来源`

每个细分行业至少生成并人工检查以下槽位：

- `行业特点`：产品、客户、渠道、产能或项目的可验证特征；
- `经营闭环`：从投入到回款的行业链条；
- `行业独特逻辑`：相对通用调查模板需要提高或降低解释力的环节；
- `调查证据`：合同、订单、采购、生产/库存、物流、票税、流水、许可、现场或第三方证据；
- `第一还款来源/授信结构`：经营回款如何形成、期限/额度与现金转换周期如何匹配；
- `行业层面准入`：进入人工授信审查前需满足的证据条件，不是自动审批结论；
- `正向逻辑链`：事实 → 经营含义 → 现金流/偿债含义；
- `反向逻辑链`：异常 → 可能原因 → 风险影响 → 必须追问的证据；
- `行业常态/误判排除`：哪些现象可能是季节性、项目制、认证切换或合理账期，如何用证据排除误判；
- `贷后监测重点` 与 `资深信贷专家追问`。

“专家规则型偏离”必须成对写出：

- `baseline`：通用模板通常看什么；
- `highWeight`：本行业必须提高权重的证据；
- `lowWeight`：本行业单独解释力低、不能替代核心证据的指标；
- `positiveChain` / `negativeChain`：正向与反向推理链；
- `falsePositive`：合理例外和反误判证据；
- `questions`：可执行的现场、电话、凭证和第三方追问；
- `coreIds` / `importantClusters`：个性指标的层级归属。

没有可靠行业依据时，复用通用模板并显式标记 `NOT_ENOUGH_DATA`，不要用行业名称自动生成具体事实、阈值或客户结论。

### 6. 映射指标簇

从指标字典解析正式 ID、名称和原表行号。每个行业把指标组织为：

`核心个性 → 重要补强 → 通用校验`

指标不是清单，而是“指标 → 所需证据 → 支持信号 → 预警信号 → 调查动作 → 人工边界”。按行业需要归入主体/授权、收入/开票、采购/供应链、生产/产能、库存/货权、应收/回款、客户/对手方、偿债/杠杆、合规/外部风险等指标簇，并保留调查阶段。

指标 ID 不在字典中时，停止把它写入正式明细，输出未匹配清单；不得临时编造正式 ID。字典只有名称没有客户值、违约标签、模型系数或校准阈值时，只生成证据调查逻辑，不生成统计风险率、分箱或自动裁决。

### 7. 生成工作簿

按现有模板保持工作表、列序、冻结窗格、公式和样式稳定。默认契约见 [workbook-contract.md](references/workbook-contract.md)。最少保留：

`说明`、`原始筛选样本`、`原始行业贷款数据`、`行业总览`、`行业规则`、`行业指标明细`、`准入及风险框架`、`指标300原表`、`来源与口径`。

总览的样本记录数、来源值合计等可审计派生字段使用可见公式，引用原始筛选样本；行业规则和指标明细用 `TRACE_CODE` 关联，不用名称查找。来源与口径页必须写出输入来源、字段限制、指标来源、版本、缺口和人工边界。

### 8. 验收、渲染和交付

在声明完成前执行：

1. 原始行数、唯一代码数、批次代码数与源数据一致；
2. 每个代码的原始行全部保留，`prod_cd_set` 与源一致；
3. 总览/规则/明细代码集合一致，`coreIds` 全部在行业指标集合内；
4. 每个正式指标 ID 能回到指标字典，新增行业有非空指标明细和核心个性指标；
5. 公式计算后扫描 `#REF!|#DIV/0!|#VALUE!|#NAME\?`；源数据已有 `#N/A` 单独记录；
6. 用 artifact-tool 渲染所有工作表，至少检查标题、表头、长文本、关键新增区的首尾行；
7. 导出 `.xlsx` 后执行 ZIP 完整性检查，并记录输出路径、覆盖统计、验证摘要和 SHA-256。

交付结果必须包含：工作簿路径、输入和运行范围、行业/原始行/指标明细数量、未匹配或冲突项、公式与视觉检查结果、人工复核边界。没有完成这些证据时，不要声称“已完成”。

## 状态和证据语义

| 状态 | 含义 |
|---|---|
| `PRELIMINARY_PASS` | 行业闭环和关键证据基本一致，进入人工授信审查；不等于批准 |
| `MANUAL_REVIEW_REQUIRED` | 存在红旗、冲突、集中度、许可/司法/合规问题或关键解释需要人工判断 |
| `NOT_ENOUGH_DATA` | 授权、时间窗、行业专属证据或指标口径不足，无法可靠判断 |
| `DEFER_OR_EXCLUDE` | 命中制度禁入、无有效许可或重大风险尚未解决，按银行制度处理 |

把行业层面的“规则假设”与客户层面的“观测证据”分开：行业规则可以提出要查什么，不能伪造客户已经满足或触发什么。

## 常见失败与红线自检

- 把 `prod_cd` 当行业主键，导致同一行业被拆成两行：回到 `TRACE_CODE` 分组并保留成员集合。
- 看到每个行业通常有固定两条记录就硬编码行数或产品代码：改为从本次源数据动态校验。
- 把 `_col0` 合计写成贷款金额、余额或风险分：回到来源字段原样口径。
- 把“资深专家判断”写成“行业平均水平”：改成相对通用模板的证据权重偏离。
- 为了补齐明细而发明指标 ID、客户值、阈值、违约率或订单量：停写，输出缺口和补证据动作。
- 用单个高风险指标自动拒绝，或用 `PRELIMINARY_PASS` 表示批准：改为人工复核状态。
- 只导出文件不渲染、不扫描公式、不做源行回溯：补齐验证证据后再交付。

## 一个合格的调用形态

用户说“继续按原始行业贷款数据分析后续 100 个细分行业，同一个行业不同 `prod_cd` 合并并更新 xlsx”时：读取源数据和旧工作簿 → 按首次出现顺序取未覆盖的 100 个 `TRACE_CODE` → 保留每个代码的全部原始行及 `prod_cd_set` → 生成行业规则、专家偏离和字典内指标明细 → 只让一个 builder 写入 → 执行上述验收并交付新版本工作簿。

详细列契约、公式和验证锚点见 [workbook-contract.md](references/workbook-contract.md)。
